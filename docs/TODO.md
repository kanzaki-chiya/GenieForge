## P0 —— 严重问题

### 1. 数据页面对比需重做为「右侧同布局只读页」
- **现状问题**：当前对比实现偏离需求。四个数据页面（科技/单位/文明/效果）的对比是「字段对比列表」（label + 基准值 → 目标值 + 应用按钮），不是用户要的样子。
- **期望**：右侧弹出一个**与左侧当前页面布局完全一致**的**只读**页面，其中「不同项」用颜色高亮，并且每个差异项带「应用」按钮。即：同一份字段表单/子表渲染两遍（左=基准可编辑，右=目标只读），逐字段对齐，差异高亮。
- **要点**：
  - 复用各页面已有的字段分组 + 控件渲染逻辑，抽成可复用表单组件（传入 `detail` + `对比模式`/`targetDetail`）。
  - 差异字段黄底、子表新增绿/删除红；每个差异点带「应用」。
  - 无差异也要完整展示（不是「无差异」空态）。
- **相关**：见 `优化设计方案.md` §4.3（原设计就是并排同布局，当前实现偏离）。

### 2. 对比数据页（DiffView 工具页）缺陷
- **现状问题**：
  1. 有 bug：某些条目的展开框是空的（`type=expand` 展开后无内容）。
  2. 显示不可读文本：变更值直接用 `JSON.stringify` 展示，字段/值可读性差。
- **期望**：
  - 先分析 AGE 同类页面的展示效果，再决定呈现方式。
  - 修复展开框空白问题；变更记录用可读形式（字段名 + 旧值→新值，含名称解析、枚举映射），而不是裸 JSON。

### 3. 对比功能重构：与「版本」融合
- **现状问题**：对比加载不优美——每次对比要手动选目标 dat 文件，且无版本概念。
- **期望**：
  1. 可**自由导入 dat 作为版本**；
  2. 可**保存当前 dat 作为版本**；
  3. 版本与 **mod 项目**挂钩——一个项目下有多个版本，可导入/保存/管理；
  4. 需要对比时**选择对应版本**即可（不再每次选文件路径）。
- **要点**：
  - 需要「项目（mod）」概念：项目目录 + 关联的多个版本快照。
  - 版本列表 UI（导入 / 保存当前 / 删除 / 对比）。
  - 与现有 `version`（保存快照）能力整合；对比入口从「选文件」改为「选版本」。
- **相关**：`优化设计方案.md` §4.5 版本历史。

### 4. 条件搜索需推广到所有数据页面
- **现状**：仅单位页实现了维度下拉搜索（AGE 式标记）。
- **期望**：科技 / 文明 / 效果页也实现同类「选择条件搜索」（维度下拉 → 标记显示 → 搜索匹配）。
- **要点**：复用单位页的维度下拉组件；为每个表定义可搜索维度（如科技：Type/Civ/Effect/费用；文明：PlayerType/科技树；效果：命令数等）。
