# 单位页面实现规划

> 单位页是 AGE 最复杂的页面：**80+ 字段、5 类子表、文明覆盖**。本文档给出可落地的实现规划，
> 字段分组已逐一映射到 genieutils 真实结构。

---

## 一、核心概念：文明覆盖（单位页独有的关键设计）

单位数据不在 `unit_headers`（那只有 exists/task_list），而在 **`Civ.units[unit_id]`**：
每个文明对每个单位有一份**独立覆盖**（`civs[0].units[74]` = Gaia 的民兵，`civs[1].units[74]` = 不列颠的民兵）。

因此单位页必须有**文明上下文**：

- **顶部文明按钮组**（AGE 截图顶部 `Ga Br Fr Go Te Ja …`）：切换当前编辑哪个文明。
- 默认选中 **Gaia（civs[0]）** = 单位的「基础定义」。
- **「复制到多文明」**：把当前单位在当前文明的覆盖，批量复制到勾选的多个文明（AGE 的 `Automatically Copy` + 文明多选 + `All/None`）。

**数据结构**：`unit_index`（已有）提供 `unit_id → Unit`（主定义），单位页编辑时需定位到
`civs[civ_id].units[unit_id]` 这一具体对象。

## 二、UI 布局

```
┌────────────────────────────────────────────────────────────────────┐
│ 工具条：搜索 | 类型筛选(下拉) | 文明按钮组(Ga Br Fr Go Te…全选/清空) │
├───────────────┬────────────────────────────────────────────────────┤
│ 单位列表       │  字段分组表单（右侧，可滚动，AGE 式密集布局）         │
│ (2382 槽，     │  Graphics ──────────────────────────────          │
│  空槽灰显)     │  [Icon][Special][Standing][Dying]  4 列紧凑        │
│               │  Damage Graphics（内嵌表格 + Add/Delete/Ins New）  │
│ Add/Delete/   │  Statistics ────────────────────────────          │
│ Copy/Paste    │  [HP][Speed][LoS][Range]  Attacks/Armors 子表      │
└───────────────┴────────────────────────────────────────────────────┘
```

- 左侧列表显示单位「内部名 + ID」，空槽（`None`）灰显「(空)」。
- 右侧表单为 **AGE 式密集分组表单**（非折叠卡片）：分组标题 + 细线分隔；字段「标签在上、控件在下」多列紧凑排列（一行 2~4 个）；子表内嵌（列头 + 数据行 + Add/Delete/Ins New）。80+ 字段靠分组顺序 + 滚动承载，不用折叠。

## 四、API 设计

现有 `GET /api/units/{unit_id}`（主定义）+ `GET /api/units/{civ}/{unit_id}`（文明覆盖）已够读。需补：

1. **字段级写**（复用 `fieldpath` 点路径）：`PATCH /api/units/{civ}/{unit_id}`，body `{field, value}`，
   路径支持嵌套与下标，如 `type_50.attacks.0.amount`、`creatable.resource_costs.1.amount`。
2. **子表增删**：`POST/DELETE /api/units/{civ}/{unit_id}/subtable/{name}`（name = attacks/armours/
   damage_graphics/resource_storages/train_locations/drop_sites），body 传新行或行下标。
3. **批量复制到多文明**：`POST /api/units/{unit_id}/copy-to-civs`，body `{from_civ, to_civs[]}`。
4. **枚举**：`GET /api/meta/unit-types`（单位类型）、`/api/meta/unit-classes`（类别）——单位类型枚举待补。

> 全部走命令栈（`dat_core.edit_field` / 复合命令），可整体撤销。

## 五、前端组件设计

| 组件 | 职责 | 复用性 |
|------|------|--------|
| `UnitListView` | 左侧单位列表（虚拟滚动 + 搜索 + 空槽标记） | 四表通用 |
| `UnitForm` | 右侧分组表单（手风琴 + 字段渲染） | 单位页专用 |
| `FieldControl` | 按字段类型渲染控件（文本/下拉/复选/数值） | **四表通用（核心复用件）** |
| `SubTable` | 子表增删改（列配置 + Add/Delete/Ins New/Copy/Paste） | attacks/armours 等通用 |
| `EnumSelect` | 枚举下拉「值 - 名称」（从 metadata 接口拉取） | 四表通用 |
| `CivPicker` | 顶部文明按钮组 + 复制到多文明 | 单位/文明页通用 |

**关键复用**：`FieldControl` + `SubTable` + `EnumSelect` 三个通用件做扎实，科技/文明/效果页就只是「换一套字段配置」。

## 六、实施步骤

1. **补枚举**：从 AGE 源码提取 `Unit.type`（单位类型）、`class_` 完整枚举 → `metadata/unit_types.json`。
2. **字段配置化**：定义 `unit.fields.ts`（分组 + 字段路径 + 控件类型 + 枚举源），表单由配置驱动渲染。
3. **API 补齐**：字段写 + 子表增删 + 复制到多文明 + meta 枚举接口。
4. **前端**：`UnitForm`（手风琴 + FieldControl）+ `SubTable` + `CivPicker`。
5. **联调**：加载真实 dat → 编辑民兵攻击/费用 → 撤销 → 复制到多文明 → 保存无损验证。

## 七、技术难点与对策

| 难点 | 对策 |
|------|------|
| 80+ 字段渲染性能 | 分组折叠 + 按需渲染（未展开分组不渲染）；表单不虚拟化，靠折叠控制 |
| 子表增删（tuple/list 不可变） | 子表操作统一「读 list → 改 → 写回新 list/tuple」，走 `fieldpath` 整体替换 |
| 文明覆盖（2382×54 槽） | 编辑只定位当前文明的对象，不做全量复制；「复制到多文明」才批量写 |
| 枚举不齐（unit.type 等） | P1 先只做已有枚举（class/资源/地形），缺失的下拉退化为纯数值输入，枚举后续补 |
| 单位空槽（None） | 列表灰显「(空)」，选中后表单显示「该文明无此单位」+「从 Gaia 复制」按钮 |
