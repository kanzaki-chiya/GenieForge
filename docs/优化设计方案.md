# GenieForge 优化设计方案（v2）

> 目标：从「能跑通的骨架」升级为「AGE 级别的专业 Mod 编辑器」，在功能强大的同时真正简化操作。
> 参考对象：Advanced Genie Editor（数据编辑）、IntelliJ IDEA（diff 对比）、现代桌面应用（UI/UE）。

---

## 一、现状问题诊断

| # | 用户反馈 | 根因分析 |
|---|---------|---------|
| 1 | 页面丑陋、无文件选择器 | 前端是「能跑就行」的占位 UI：无主题设计、无布局规划；dat 路径靠手输 `el-input` |
| 2 | 菜单只有科技栏可用 | 6 个菜单项都在，但除「科技」外其余页面要么是空壳占位、要么信息量极少，显得「没有」 |
| 3 | 配置页 github/apikey/端口冗余 | 这些是早期预留，原需求（桌面工具）确实不需要；更新仓库应固定 |
| 4 | 补丁页要粘贴 YAML 且直接应用 | 补丁被设计成「面向 Agent 的文本接口」，缺面向人的可视化编辑 + 预览对比 |
| 5 | diff 缺图形化高亮 | diff 结果用纯表格列出 JSON，无行级/字符级高亮，无左右双栏 |
| 6 | 加载 dat 报 400 Errno 13 | 游戏运行时 dat 文件被独占锁定（Permission denied），且错误提示不友好 |

**核心矛盾**：功能后端已具备，但**没有做成"编辑器的样子"**。AGE 的本质是「高密度数据表格 + 即时编辑」，我们的本质还是「接口调试页」。

---

## 二、设计原则

1. **以"编辑"为核心**：所有数据浏览页都要能直接改（行内编辑），而非只读展示。
2. **表格密集型 UI**：像 AGE 一样用高密度表格承载上千条记录，配合虚拟滚动、搜索、筛选、列排序。
3. **键盘 + 鼠标双操作**：复制/粘贴（Ctrl+C/V）、行内编辑、批量选择、快捷键导航。
4. **所见即所得 + 安全**：修改即时预览、可撤销（命令栈）、补丁应用前先看 diff 再确认。
5. **深色专业主题**：开发者工具偏好深色，降低长时间使用疲劳。

## 三、UI/UX 整体重设计

### 3.1 信息架构（菜单重组）

现菜单 `概览/科技/对比/补丁/版本/设置` 缺「单位/文明/效果」入口，且「补丁/版本」对普通用户偏技术。重组为：

```
┌─ 工作台（原概览）：dat 加载、最近文件、全局搜索、数据总览
├─ 数据浏览（核心，参考 AGE 标签页）
│   ├─ 科技 Techs
│   ├─ 单位 Units
│   ├─ 文明 Civs
│   └─ 效果 Effects
├─ 工具
│   ├─ 对比差异 Diff（双栏高亮）
│   └─ 补丁 Patches（可视化）
└─ 版本历史（含 Git 快照、回滚）
（设置并入右上角齿轮图标，不放主菜单）
```

### 3.2 视觉规范

- **主题**：深色为主（背景 `#1E1F22`、面板 `#2B2D30`、边框 `#3C3F41`，对齐 IDEA Darcula）。
- **颜色语义**：涨/增益用暖色，跌/减益用冷色（数据对比沿用中文习惯：新增绿、删除红，修改黄——见 §5.2）。
- **字体**：等宽字体（Consolas/JetBrains Mono）用于数值列，保证对齐。
- **间距**：紧凑型（表格行高 28px），适配大数据量。
- **图标**：侧栏与操作按钮配图标（Element Plus 图标集）。

### 3.3 布局（三栏经典编辑器结构）

```
┌──────────┬─────────────────────────┬──────────────────────┐
│ 侧栏导航  │  列表/表格区（主）        │  详情/属性面板（右，可收起）│
│ (180px)  │  搜索+筛选+虚拟滚动表格    │  字段编辑 + 引用跳转      │
└──────────┴─────────────────────────┴──────────────────────┘
```

- 左侧：导航 + 已加载 dat 状态。
- 中间：数据表格（AGE 式主视图）。
- 右侧：选中记录的属性编辑面板 + 正向/反向引用（关联跳转）。

### 3.4 文件选择器（替换手输路径）

- **桌面壳（pywebview）**：调用系统原生文件对话框（`webview.windows[0].create_file_dialog`，`OPEN` 模式），过滤 `*.dat`。
- **浏览器模式**：`<input type="file">` 兜底。
- **最近文件**：记录最近打开的 dat 路径（本地配置），首页一键点开，不再每次手输。
- **游戏目录探测**：设置里「自动探测 AoE2 安装目录」（查注册表 `HKCU\Software\Microsoft\...\Age of Empires II: DE` / 常见安装路径），一键定位 dat。

## 四、各模块详细设计

### 4.1 工作台（首页）

- 大按钮「打开 dat」+ 最近文件列表（路径 + 版本 + 表数量 + 修改时间）。
- 加载后显示数据总览卡片：科技/单位/文明/效果 数量、dat 版本、是否已修改（dirty 标记）。
- 全局搜索框：跨表搜名称/ID，回车直达对应记录。

### 4.2 数据浏览器 —— 对齐 AGE 的「列表 + 分组表单」编辑器

> 核心纠正：不做"大表格 + 简单详情"，而是 **左侧记录列表 + 右侧完整字段分组表单**（master-detail）。
> 完整字段已从 genieutils 真实结构提取，按逻辑分组，控件类型对齐 AGE（枚举下拉、复选框、子表、数组并排）。

**布局（四表统一）：**

```
┌───────────┬──────────────────────────────────────────────┐
│ 记录列表   │  字段分组表单（可滚动，多分组）                  │
│ 搜索+筛选  │  ┌─ 基础 ────────────────┐                   │
│ 虚拟滚动   │  │ name / type / class … │                   │
│ Add/Delete │  ├─ 语言 ────────────────┤                   │
│ Copy/Paste │  ├─ 费用 / 前置 / 战斗 ──┤                   │
│            │  ├─ 子表（增删改）───────┤                   │
│            │  └─ 引用（跳转）─────────┘                   │
└───────────┴──────────────────────────────────────────────┘
```

**通用能力：**
1. 左侧列表：搜索 + 筛选（类型/文明）+ 虚拟滚动 + Add/Delete/Insert/Copy/Paste/Ins Copies（对齐 AGE）。
2. 右侧表单：字段按逻辑分组，**每个字段用「标签 + 控件」**，控件类型按字段语义：
   - 数值/字符串 → 文本框（改完入撤销栈）
   - 枚举 → **下拉「值 - 名称」**（如 `3 - Gold`、`102 - Disable Tech`）
   - 布尔 → 复选框（repeatable / paid / exists）
   - 引用 → **下拉 + 点击跳转**（effect_id、required_techs、tech_tree_id…）
   - 数组 → **并排重复控件**（前置科技×6、费用×3）
   - 列表字段 → **子表**（可 Add/Delete/Insert，行内编辑）
3. 复制粘贴：单元格复制、整行复制、Excel 区间粘贴、右键「复制为补丁」。
4. 批量：勾选多行 → 批量改字段；**「复制到多文明」按钮组**（对齐 AGE 顶部文明多选）。

**各表字段分组（完整字段，基于 genieutils 真实结构）：**

**① 科技 Tech（14 字段）**

| 分组 | 字段 | 控件 |
|------|------|------|
| 基础 | name / type / civ / repeatable / full_tech_mode / icon_id | 文本 / 下拉(科技类型) / 下拉(文明) / 复选框 / 下拉 / 文本 |
| 语言 | language_dll_name / _description / _help / _tech_tree | 文本 + 显示对应本地化文本 |
| 前置 | required_techs[6] + required_tech_count | 6 组下拉(选科技) + 文本 |
| 费用 | resource_costs[3]（type/amount/flag） | 3 组：下拉(资源类型) + 数值 + 复选框(paid) |
| 效果 | effect_id | 下拉(效果) + 跳转 |
| 研究位置 | research_locations | 子表（location 下拉 + research_time + button_id） |

**② 单位 Unit（80+ 字段，按 AGE 分组）**

| 分组 | 字段 | 控件 |
|------|------|------|
| 基础 | name / type / class_ / id / copy_id / base_id | 文本 / 下拉(单位类型) / 下拉(类别=护甲类) / 文本 |
| 战斗 | hit_points / line_of_sight / speed / garrison_capacity / type_50(base_armor, max_range, reload_time) | 数值 |
| 攻击 | type_50.attacks | 子表（类别下拉 + 数值） |
| 护甲 | type_50.armours | 子表（护甲类下拉 + 数值） |
| 费用/生产 | creatable.resource_costs[3] / creatable.train_locations | 3 组资源 + 子表(训练位置) |
| 图形 | standing_graphic / dying_graphic / icon_id | 文本 / 数值 |
| 语言 | language_dll_name / _creation / _help / _hotkey_text | 文本 |

**③ 文明 Civ**

| 分组 | 字段 | 控件 |
|------|------|------|
| 基础 | name / player_type / icon_set / tech_tree_id / team_bonus_id | 文本 / 下拉 / 数值 / 下拉(科技树) + 跳转 / 下拉(团队加成) |
| 资源 | resources[500] | **500 项列表**（`序号 - 值 - 资源名`，行内编辑，粉色高亮当前项） |
| 单位 | units[2382] | 子表（可切换、批量复制到多文明） |

**④ 效果 Effect**

| 分组 | 字段 | 控件 |
|------|------|------|
| 名称 | name | 文本 |
| 命令 | effect_commands | **子表**（type 下拉[effect_types.json 完整枚举] + a/b/c/d，每行一条） |

**枚举来源（下拉数据）：** 资源类型 / effect 类型 / 护甲类型 / 文明资源 / 地形 均已内置在 `backend/metadata/*.json`，可直接驱动下拉「值 - 名称」。

### 4.3 对比差异（Diff）—— 原页面右侧弹窗 + 逐项应用

> 不做独立 diff 页，而是**在原编辑器页面（科技/单位/效果/文明）基础上，右侧弹出「目标文件」
> 的同页面视图**，布局与原页面完全一致，字段/条目逐行对齐，差异高亮，每个差异点可**单独应用**
> （把目标值合并进当前基准文件）。本质是 Beyond Compare 式「并排 + 逐项合并」，对象是字段表单。

**统一交互模型：**

```
┌ 顶部：基准 [路径] ↔ 目标 [路径]（弹窗）     [应用全部差异] ┐
├──────────────┬──────────────────┬──────────────────────────┤
│ 记录列表      │ 基准文件字段表单   │ 目标文件字段表单（弹窗）    │
│ (原页面左列)  │ (原页面右侧)      │ 布局一致，差异高亮 + [应用] │
└──────────────┴──────────────────┴──────────────────────────┘
```

**差异高亮规则（四表统一）：**
- 标量/数组字段值不同 → 该词条**黄底**高亮，右侧「应用」按钮把目标值写入基准。
- 子表/列表条目数不一致 → 新增条目**绿底**、删除条目**红底**，各带「应用」（新增=插入，删除=移除）。
- 无差异 → 普通显示，不干扰视线。
- 每个差异点「应用」走命令栈，可逐个撤销；另提供「应用全部差异」一键合并。

**四表差异化实现：**

| 页面 | 对比载体 | 差异形态 |
|------|---------|---------|
| 科技 | 字段表单 + 费用数组 + 研究位置子表 | 标量差异（effect_id）、数组差异（金费）、子表增删（研究位置） |
| 单位 | 字段表单 + 攻击/护甲子表 + 资源存储 | 标量差异（生命/护甲）、**子表条目增删**（攻击类新增/删除） |
| 效果 | **纯命令子表**（type/a/b/c/d） | 表格逐行比对，条目修改黄、新增绿、删除红 |
| 文明 | 字段表单 + **500 项资源列表** + 单位覆盖 | 标量差异（团队加成）、资源列表逐项比对 |

- **跳转**：点击差异记录 → 直接打开该记录在浏览器中的编辑视图。
- **导出**：将当前对比差异一键「生成补丁」（复用现有 `patch/generate`），并直接预览。

### 4.4 补丁（Patches）—— 可视化，不再「粘贴 YAML + 直接应用」

**补丁编辑器（表单化，替代手写 YAML）：**

1. **补丁列表**：左侧列出补丁文件（`patches/` 目录扫描），可新建/加载/删除。
2. **步骤编辑**：每个补丁由多个「步骤」组成，步骤用表单填：
   - 目标：表（下拉）+ 匹配方式（名称 / 名称模式 / 签名，下拉切换）
   - 操作：字段（下拉，按表列出可用字段）+ 运算（set/add/multiply/… 下拉）+ 值
3. **应用前预览（关键，解决"直接应用"）：**
   - 点「预览」→ 解析每个步骤的目标命中情况（命中 N 条 / 冲突 / 未命中），逐条列出「目标 → 字段 → 旧值 → 新值」。
   - 高亮冲突与未命中的步骤，让用户改。
4. **确认应用**：预览无误后点「应用」→ 走命令栈（可整体撤销），应用结果显示成功/冲突/跳过。
5. **仍保留 YAML 视图**：表单 ↔ YAML 双向切换（面向高级用户/Agent），但默认表单。

### 4.5 版本历史

- 列表展示每次保存的快照（时间 / 描述 / 哈希 / 是否当前）。
- 「对比」按钮：任选两个版本 → 跳到 diff 双栏视图。
- 「回滚」按钮：加载历史版本（走 `version/checkout`，先提示备份）。

## 五、关键功能设计

### 5.1 数值复制 / 粘贴（对标 AGE）

- 后端新增 `PATCH /api/{table}/{id}` 已支持点路径字段修改（走命令栈），前端表格直接调用。
- 粘贴用「事务」：一次粘贴 N 个值 = 一次命令栈提交，可一键整体撤销。
- 类型安全：粘贴值做类型校验（数值/枚举/字符串），非法值红色提示不落库。

### 5.2 diff 高亮配色（git/IDEA 惯例）

| 变化 | 颜色 |
|------|------|
| 新增（added） | 绿底/绿字 |
| 删除（removed） | 红底/红字 |
| 修改（modified） | 黄底 + 旧值删除线红、新值绿 |

（注：diff 属「文件差异」场景，遵循 git/IDEA 全球惯例「绿新增、红删除」；
「红涨绿跌」仅适用于股票/涨跌类数据可视化，此处不采用。）

### 5.3 快捷键

`Ctrl+O` 打开 dat · `Ctrl+S` 保存 · `Ctrl+Z/Y` 撤销/重做 · `Ctrl+F` 搜索 · `Ctrl+C/V` 复制粘贴 · `Ctrl+E` 导出补丁。

## 六、错误处理（含 Errno 13）

1. **加载前预检**：`open(path,'rb')` 探测可读性，失败直接返回友好提示：
   - `PermissionError [Errno 13]` → 「dat 文件被占用（可能游戏正在运行），请关闭游戏后重试」。
2. **路径校验**：文件不存在 / 非 .dat / 是目录 → 明确提示。
3. **加载进度**：dat 解析约 10s，加载中显示进度条/动画，避免"卡死"错觉。
4. **保存前备份**：写回前自动备份原文件（`xxx.dat.bak`），失败可恢复。
5. **统一错误弹窗**：所有接口错误用统一 Toast/对话框，带可复制的错误详情。

## 八、分阶段实施计划

| 阶段 | 内容 | 交付 |
|------|------|------|
| **P1 UI 基础** | 深色主题、三栏布局、图标、文件选择器、最近文件、菜单重组 | 整体观感到位 |
| **P2 数据浏览器** | 虚拟滚动表格 + 搜索筛选排序 + 行内编辑 + 复制粘贴 + 右键菜单 + 详情面板 | 科技/单位/文明/效果 四页可用，对标 AGE 核心编辑 |
| **P3 diff 高亮** | 双栏 + 三级高亮 + 字符级 diff + 跳转 + 导出补丁 | 对比页面图形化 |
| **P4 补丁可视化** | 表单化补丁编辑器 + 应用前预览 + 确认应用 + YAML 双向切换 | 补丁不再"粘贴即应用" |
| **P5 配置精简 + 错误处理** | 删冗余配置、Errno 13 友好提示、加载进度、保存备份 | 报错与配置清爽 |
| **P6 打磨** | 快捷键、批量编辑、全局搜索、性能（虚拟滚动）、打包发布 | 达到可替代 AGE 的可用度 |

## 九、与 AGE 的能力对照（目标）

| 能力 | AGE | GenieForge 现状 | 本方案目标 |
|------|-----|----------------|-----------|
| 数据表格编辑 | ✅ | 只读表格 | ✅ 行内编辑 + 批量 |
| 数值复制粘贴 | ✅ | ❌ | ✅ |
| 单位/科技/文明/效果浏览 | ✅ | 仅科技有表格 | ✅ 四表齐全 |
| 文件选择 | ✅ | 手输路径 | ✅ 原生对话框 |
| 修改撤销 | ❌ | ✅ 命令栈 | ✅ 保留 |
| 语义化补丁 | ❌ | ✅ | ✅ 可视化化 |
| diff 图形化 | 部分 | ❌ | ✅ IDEA 式 |
| 中文显示名 | ❌ | ✅ | ✅ 保留 |

**结论**：后端能力（无损写回、命令栈撤销、语义补丁、引用索引）已领先 AGE；本方案把「短板」补齐——前端做到 AGE 的编辑体验 + IDEA 的 diff 可视化，即可真正替代 AGE。
